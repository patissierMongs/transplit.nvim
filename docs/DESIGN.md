# 설계 결정 기록

transplit.nvim과 screen-explain을 만들면서 내린 판단을 **시간순으로** 적은 기록이에요.
각 항목은 **상황 → 관찰·측정 → 판단 → 결과** 순서예요. 틀렸던 판단도 그대로 남겼어요.

> **측정 환경:** ThinkPad X220 (Intel i5-2520M, 2011년), Arch Linux, sway, Neovim 0.12, Claude Code CLI 2.1.x.
> 수치는 한 기기에서 한두 번 잰 값이라 **경향을 보는 용도**예요. 벤치마크가 아니에요.

## 2026-09-18

### 1. 출발점: README.md의 md 오류
- **상황:** nvim(LazyVim)으로 nginx 소스의 README.md를 열면 오류가 잔뜩 뜸.
- **관찰:** LazyVim의 markdown extra가 켠 `markdownlint-cli2`가 모든 규칙을 적용. 87개 중 줄 길이(MD013) 41개, 제목 주변 빈 줄(MD022) 30개 등 스타일 규칙.
- **판단:** 남의 README를 **읽을 때** 스타일 경고는 소음. 다만 프로젝트에 자체 설정이 있으면 그걸 존중해야 함 → "프로젝트 설정이 없을 때만 전역 기본 설정" 방식.
- **실수:** 처음엔 전역 설정 파일(`~/.markdownlint-cli2.yaml`) 자체가 "프로젝트 설정"으로 잡혀서 적용이 안 됐음. 설정 파일을 위로 찾아 올라가는 범위를 `$HOME` 전에서 멈추게 해서 해결.
- **결과:** 87 → 38개. 남은 건 실제 형식 오류라 그대로 둠.
- **여기서 나온 아이디어:** "터미널에서 보는 걸 LLM으로 번역하면 좋겠다."

### 2. 번역 창을 어디에 띄울까
- **요구:** 로그를 보다가 번역을 옆에 띄우고, 스크롤하면 같이 따라가고, 양식은 최대한 그대로.
- **후보:** tmux pane / sway 창 / nvim 분할 창.
- **판단:** tmux·sway는 **서로 다른 프로세스**라 스크롤 위치를 맞출 수단이 없음. nvim에는 창 두 개의 스크롤과 커서를 묶는 `scrollbind`/`cursorbind`가 원래 있음 → nvim 분할 창.
- **정렬 조건:** 번역 창은 원문과 **줄 수가 정확히 같아야** 함. 긴 줄이 접히면 정렬이 깨져서 두 창 모두 `nowrap`. 아직 번역 안 된 줄은 원문을 흐리게 보여줘서 레이아웃이 밀리지 않게 함.

### 3. 첫 구현과 첫 측정
- **구현:** 보이는 범위의 줄을 JSON 배열로 `claude -p --model haiku`에 보냄.
- **측정:** 호출 하나에 약 10초, 15줄 묶음에 **56초**. 쓸 수 없는 속도.
- **버그:** `nvim_win_call`은 반환값을 **하나만** 넘겨줌. `w0`, `w$`를 두 값으로 받으려다 `nil` 연산 오류. 테이블로 감싸서 해결.

### 4. 값을 가리고 패턴 단위로 번역
- **관찰:** nginx 로그는 시간·PID·IP·경로만 다르고 문장 패턴은 반복됨.
- **판단:** 시간, `[error]`, IP, URL, 경로, 따옴표 문자열, 숫자를 `⟪a⟫` 같은 자리표시자로 바꾸고 **고유한 템플릿만** 번역한 뒤 값을 원래대로 끼워 넣음.
  - LLM이 값을 **건드릴 수 없음** → 양식 보존이 구조적으로 보장됨
  - 같은 모양의 줄 수천 개가 번역 한 번으로 해결됨
  - 번역 결과에 자리표시자가 **정확히 같은 집합**으로 있을 때만 채택(순서는 바뀌어도 됨)
  - 값만 있는 줄(access log 등)은 아예 보내지 않음
- **결과:** 120줄 로그 → 번역할 패턴 **4개**.
- **나중에 추가:** 줄 앞뒤 공백은 LLM에 맡기지 않고 로컬에서 다시 붙임(man 페이지·YAML 들여쓰기 보호).

### 5. 문맥을 얼마나, 어떻게 보낼까
- **사용자 제안:** 파일 경로·이름, 파일 맨 위·아래 몇 줄, 커서 주변 줄을 보내고, **LLM이 더 필요하다고 판단하면** 파일 크기·폴더 구조(tree)를 추가로 보내자.
- **평가:** 방향은 맞음. 경로와 앞뒤 줄만으로도 "이게 무슨 파일인지"는 충분히 판단됨.
- **바꾼 점 ①:** "더 필요한지"를 묻는 단계는 뺌. 왕복 한 번이 **5~30초**인데, 트리는 항목 80개·깊이 2로 제한하면 **수백 토큰**. 처음부터 같이 보내는 게 싸다.
- **바꾼 점 ②:** 원본 문맥은 **파일당 한 번만**. 첫 번역 요청에서 번역과 함께 "이 파일이 뭔지, 줄 형식, 번역하면 안 되는 용어"를 3~6문장 요약(profile)으로 **같은 응답에** 받아 캐시하고, 이후엔 요약만 보냄. 호출 수는 늘지 않고 용어도 일관됨.
- **보안:** 트리는 이름과 크기만, 파일 내용은 보내지 않음.
- **부작용과 수정:** 요약이 "No such file or directory" 같은 **오류 메시지까지 번역 금지 용어**로 분류해서 영어로 남음 → "식별자·필드 이름만 번역 금지, 사람이 읽는 메시지는 번역"으로 프롬프트 수정.

### 6. CLI가 왜 느린가
- **측정 ①:** 같은 한 줄 번역이 9.2초. 병목을 찾으려고 옵션을 하나씩 끔 → claude.ai 커넥터(MCP)·설정 로딩을 끄면(`--strict-mcp-config --setting-sources=`) **4.8초**.
- **측정 ②:** 스트림 출력을 보니 haiku가 thinking 블록을 먼저 만들고 있었음. `MAX_THINKING_TOKENS=0`으로 40줄 번역 **118초 → 30초**.
- **판단:** 번역처럼 형식이 정해진 작업엔 thinking이 이득이 없음. 프로젝트의 CLAUDE.md가 프롬프트에 섞이지 않게 작업 폴더도 캐시 폴더로 고정.
- **결과(4·5·6 합산):** 120줄 로그 첫 번역 **95초 → 9초**. 두 번째부터는 캐시로 1초 안.

### 7. 설명 기능
- **요구:** 번역과 별개로, 현재 줄이 **무슨 뜻이고 왜 중요한지** 설명.
- **판단:** 설명은 길어서 기다리는 시간이 체감됨 → **스트리밍**. 섹션을 의미 / 문맥 / 실무 포인트 / 참고로 고정해서 매번 같은 구조로 읽히게 함.
- **결과:** 첫 글자까지 약 3초. 실제 nginx 로그에서 `server: localhost`인데 `host: "example.com"`인 걸 보고 "default_server로 라우팅됐다"를 짚어냄.

### 8. nginx 전용에서 범용으로
- **요구:** docker 설정, man 페이지 등 TUI 전반에서 쓰고 싶음.
- **변경:**
  - man 페이지(`man://tar(1)`)나 파이프 출력은 **파일이 아님**. 크기와 트리를 보내지 않음(man 페이지는 연 위치의 폴더와 무관).
  - 프롬프트: 설정 파일·코드에서는 주석과 설명 문장만 번역, 설명 섹션은 파일 종류에 맞게 조정.
  - `MANPAGER='nvim +Man!'`가 이미 설정돼 있어서 man 뷰어는 바꿀 필요 없었음.
- **문제:** man 페이지 번역이 121초 뒤 "해석 불가"로 실패. 여러 줄에 걸친 문장을 모델이 합치거나 나눠서 **줄 수가 어긋남**.
- **판단:** 실패하면 묶음 크기를 절반으로 줄여 재시도(최소 4). 재시도 경로가 실제로 실행되는 건 확인하지 못함.

### 9. 시각화 1차: Mermaid + 브라우저
- **요구:** compose면 아키텍처·네트워크·포트 매핑, 코드면 흐름, tcpdump면 페이로드. 상황에 맞게.
- **판단:**
  - nvim 안에 **작은 HTTP 서버**(libuv)를 띄우고 브라우저가 1초마다 새 버전을 확인. 별도 프로세스 없이 nvim과 수명이 같음.
  - `127.0.0.1`에만 바인딩, 경로에 **랜덤 토큰**(다른 사이트가 문서를 읽거나 LLM 호출을 일으키지 못하게), 문서 속 HTML은 문자열로만 표시.
  - Mermaid 렌더링 오류를 **페이지가 nvim으로 되돌려 보내고** LLM이 고침(최대 2회).
  - 현재 파일이 **상대 경로로 참조하는 파일**도 보냄(compose의 `./conf/nginx.conf`, `build: ./app`의 Dockerfile). 절대 경로·`.env`·키 파일은 제외.
- **결과:** compose 시각화가 참조된 nginx.conf까지 읽고 "컨테이너 안의 `127.0.0.1:8080`은 호스트가 아니라 자기 자신"이라는 설정 오류를 찾아냄.

### 10. Mermaid 말고 다른 도구는?
사용자 요청으로 비교. D2는 실제로 받아서 돌려봤고 나머지는 저장소 패키지 존재만 확인.

| 도구 | 강점 | 약점 |
|---|---|---|
| Mermaid | 다이어그램 종류가 가장 많음(packet, pie, xychart). LLM이 가장 익숙함 | 문법 오류가 잦고, **브라우저에서 그려야만** 오류를 알 수 있음 |
| **D2** | 아키텍처 레이아웃이 깔끔. **컴파일 50ms, 오류에 줄:열**. 터미널 텍스트 출력 지원 | packet·pie·xychart 없음. 텍스트 출력에서 **한글이 깨짐**(두 칸 폭) |
| Graphviz | 큰 그래프에서도 안정적 | 외형이 투박, 시퀀스 다이어그램 없음 |
| PlantUML | UML이 가장 완전 | JVM이라 무겁고 느림 |
| LLM이 그린 ASCII | 설치 불필요 | 박스와 선이 잘 어긋나고 검증 불가 |

- **터미널 이미지 제약:** foot는 sixel을 지원하지만 nvim 이미지 기능(snacks.image 등)은 kitty 계열만 지원 → nvim 안에 이미지는 사실상 불가.

### 11. "꼭 이미지여야 하나? Emacs는?"
- **사용자 질문**이 방향을 바꿈.
- **확인:** 설치된 Emacs 30.2가 Wayland 네이티브(pgtk)이고 SVG 표시 지원.
- **판단:** 3단계 보기.
  1. **nvim 안 텍스트**(D2 텍스트 출력): 창 전환 없이 즉시
  2. **Emacs SVG**(`ge`): 한글 라벨 문제 없음, 파일이 바뀌면 다시 읽음
  3. **브라우저**(`gb`): D2에 없는 packet·pie·xychart만 Mermaid로
- **결과:** Mermaid는 세 종류로만 제한. D2가 주력이 되면서 **로컬 컴파일 검증**이 가능해짐 → 브라우저를 거치지 않고 오류를 즉시 LLM에 되돌림.

### 12. D2 라벨의 한글 문제
- **관찰:** "라벨은 영어로만"이라고 프롬프트에 써도 모델이 "추정", "체크" 같은 한글을 넣음 → 텍스트 다이어그램이 틀어짐.
- **판단:** 프롬프트만으로는 못 막음 → **라벨에 비ASCII 문자가 있으면 컴파일 오류처럼 취급**해서 자동 수정 루프에 태움. 설명과 표는 여전히 한글.
- **측정:** 검사 없이 17초 / 검사 포함 **44초**(수정 2회), 텍스트 다이어그램 안 한글 **0자**.
- **트레이드오프:** 정확도를 위해 약 27초를 더 씀. 프롬프트를 더 강하게 고쳤지만 그 효과는 다시 측정하지 않음.

### 13. 전체 번역·전체 설명
- **판단:** 전체 번역은 보이는 곳부터 하고 나머지를 한 번 훑으며 최대 3개 요청을 동시에 보냄. 단 **첫 요청이 profile을 만들 때까지는 하나만** 보내서 요약을 중복 생성하지 않음.
- 큰 파일(60KB 초과) 설명은 앞 150줄·뒤 150줄·**반복되는 줄 패턴**(마스킹 템플릿과 등장 횟수, 첫·마지막 줄)으로 요약해서 보냄. 로그의 "무엇이 몇 번, 언제부터 언제까지"가 적은 토큰으로 전달됨.

### 14. 버그: 전체 번역하자마자 E539
- **재현:** `./configure --help | nvim -`에서 전체 번역.
- **원인:** 창 상단 표시줄(winbar)은 **statusline 서식 문자열**이라 진행률의 `%`가 서식 기호로 해석됨.
- **수정:** `%` → `%%` 이스케이프를 표시줄 쓰는 곳 전부에 적용.

### 15. 버그: 서로 다른 파이프 출력이 캐시를 공유
- **원인:** 이름 없는 버퍼의 캐시 키가 전부 `[buffer 1]` → 다른 명령어 출력끼리 profile과 번역을 공유.
- **수정:** 내용 앞 20줄의 **SHA-256**으로 키를 만듦.
- **덤:** 같은 명령어 출력은 다음에 열어도 캐시 재사용 → `configure --help` 190줄 재열기 **32초 → 2초**.

### 16. 버그: 전체 번역이 끝났는데 원문이 남아 있음
- **관찰:** 129줄이 원문 그대로. 캐시를 열어보니 번역은 다 들어 있었음.
- **원인:** 번역 창은 현재 페이지 ± 1페이지만 다시 그림. 화면 밖 줄은 스크롤해야 그려짐 → 번역 창에서 `/` 검색이 안 됨.
- **수정:** 전체 번역이 끝나면 파일 전체를 한 번 다시 그림. 129 → 17줄(남은 건 옵션 이름·CPU 이름뿐이라 번역할 게 없음).

### 17. screen-explain: 지금 화면을 설명하는 키
- **요구:** ThinkVantage 키로 "지금 화면"을 설명, 새 pane에서.
- **판단:**
  - 새 pane을 열기 **전에** 캡처(pane이 화면을 가리지 않게).
  - 문맥: 포커스된 창의 앱·제목, 터미널이면 **프로세스 트리를 따라가서** 안에서 실행 중인 명령과 작업 폴더. 파일 내용은 읽지 않음.
  - `claude -p`에 **Read 도구만** 허용해서 스크린샷 파일을 읽게 함.
- **검증:** 실제 화면 대신 가짜 터미널 오류 이미지(SVG → PNG)로 테스트. 캡처가 외부로 나가는 걸 테스트 단계에서 피하려고.

### 18. ThinkVantage가 반응하지 않음 (가장 오래 헤맨 부분)
1. **처음:** `XF86Launch1`로 연결 → 반응 없음.
2. **wev로 확인:** 키가 아니라 **휠 스크롤**(`wl_pointer axis`) 이벤트가 찍힘.
3. **원인 ①:** keyd가 `[ids] *`로 **모든 입력 장치**를 가로채는데, keyd의 가상 키보드는 이 키를 지원하지 않음. `/proc/bus/input/devices`의 키 비트맵으로 확인. → keyd에서 `ThinkPad Extra Buttons`(`17aa:5054`)만 제외. 스크롤은 멈춤.
4. **내 실수:** 커널 드라이버 키맵만 보고 키 코드를 `KEY_VENDOR`(368)로 판단해서 연결을 바꿈. 이어서 "xkb 키 코드 범위(최대 255) 밖이라 안 된다"는 가설까지 세우고 udev 수정을 안내함.
5. **실제:** systemd 기본 hwdb가 이미 `KEYBOARD_KEY_17=prog1`로 바꿔서 보내고 있었음(`udevadm info`로 확인) → xkb **156** = `XF86Launch1`. **처음 이름이 맞았고**, 막았던 건 keyd뿐이었음.
- **교훈:** 커널 코드표를 보기 전에 **udev가 적용한 실제 매핑**(`udevadm info`)부터 확인. 가설을 안내하기 전에 확인 가능한 사실부터 볼 것.

### 19. 길게 누르기가 안 되는 키
- **요구:** 짧게 누르면 설명, 길게 누르면 질문.
- **관찰:** 실행 기록을 보니 길게 눌러도 **누르기와 떼기가 같은 초에** 들어옴.
- **원인:** ThinkVantage는 EC 핫키. EC가 신호를 한 번만 보내고 커널이 누르기·떼기를 동시에 만듦 → 누른 시간을 소프트웨어로 알 수 없음.
- **판단:** **0.4초 안에 두 번 누르기**로 대체. 두 프로세스가 경쟁하지 않게 상태 파일에 `flock`.
- **대가:** 한 번 누르기는 두 번째 입력을 기다리느라 0.4초 늦게 뜸.
- **검증:** 한 번 → 설명 / 0.2초 간격 두 번 → 질문 **한 번만** / 0.6초 간격 → 설명 두 번.

## 알려진 한계와 남은 과제
- **API 백엔드(curl) 경로는 미검증:** API 키 없이 CLI로만 테스트함.
- **실사용 확인이 필요한 부분:** Emacs 인라인 SVG 표시, 브라우저의 Mermaid 렌더링과 오류 되돌림. headless 테스트로는 확인하지 못함.
- **번역 품질 평가 체계가 없음:** 품질은 눈으로만 확인. 고정된 예제와 기대 출력으로 회귀 테스트를 만들 여지가 있음.
- **D2 텍스트 출력:** 긴 라벨이 박스 테두리를 뚫고 지나감. D2 텍스트 렌더러의 한계라 복잡한 다이어그램은 `ge`로 봐야 함.
- **캐시가 계속 커짐:** 오래된 항목을 지우는 정책이 없음.
- **아주 큰 파일(10만 줄 이상)의 전체 번역:** 완료 후 전체를 한 번 다시 그리는 비용을 재보지 않음.
